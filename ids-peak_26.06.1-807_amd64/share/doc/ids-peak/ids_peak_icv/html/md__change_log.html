Changelog

Version 1.5.0

Features

  • Added support for more pixelformats when subtracting images. All unpacked formats except ones with an alpha channel are now supported.
  • Added support for more pixelformats when thresholding images. All single channel unpacked formats are now supported.
  • Added support to load Mono16 images from file.
  • Improved performance of the following:
    • XYZ Image creation
    • Point Cloud transformation to workspace
    • Querying Points from a Point Cloud
    • Threshold processing
    • Painting
    • Drago Tonemapping

Bug Fixes

  • Fixed incorrect image deep copy. During a deep copy of an image, the associated image region was only shallow copied.

Version 1.4.0

Features

  • Added support for writing images in .hdr format.
    • C++: imageWriter.Write("file_name.hdr", image)
    • Python: image.save("file_name.hdr")
    • .NET: imageWriter.Write("file_name.hdr", image)
  • Added support for reading images in .hdr format.
    • C++: Image("file_name.hdr", pixelFormat)
    • Python: Image.create_from_file("file_name.hdr", forced_pixel_format=pixel_format)
    • .NET: new Image("file_name.hdr", pixelFormat)
  • Point clouds now support RGB color attributes.
  • The Python Image class now supports deep copying via image.copy().

  • Added new PFNC pixel formats RGB32f and Mono32f

    These are the successor of RGB32fIDS and Mono32fIDS, which are now deprecated and will be removed in a future version. The deprecated pixel formats have already been replaced in HDR-like functions, as they are experimental. Other functionality is unaffected, but will be replaced in future versions.

  • HDR: Removed the experimental status from all existing HDR-related functionalities and migrate them out of the experimental namespace.

  • HDR Response Curve I/O: Added support for saving and loading Camera Response Curves to and from disk.

    This allows you to perform the computationally expensive estimation step only once and reuse the resulting curve for future HDR processing.

  • HDR NaN Handling: Updated the treatment of under- and overexposed pixels across all input images.

    These pixels are now clamped to the HDR image's global minimum and maximum values, respectively. Additionally, the processing region is now strictly limited to valid, properly exposed pixels.

  • HDR tone mapping: Changed tone mapping interface to be able to provide multiple different tone mapping algorithms with different parameters.
  • HDR tone mapping: Replaced the Reinhard tone mapping algorithm with Drago.
  • Speed up image conversion in image.ConvertPixelFormat for packed source images.
  • Added functionality to choose whether to zero initialize images, when created from size.
  • Added a method to the C++ interface to convert the pixel format of an image into a previously created destination image (see Image::ConvertPixelFormat ).
  • (Experimental) HDR tone mapping: Added linear tone mapping algorithm.

Bug Fixes

  • Fixed issues throughout all interfaces, that metadata was not retained when the image was processed by an algorithm

Documentation

  • The link to the calibration plate description file in the Camera Calibration guide now points to the correct location.

Version 1.3.0

Breaking changes

  • Python: Move Rotation class from ids_peak_icv.datatypes to ids_peak_icv.pipeline.datatypes.

Major Milestone

  • New .NET interface: First release of the dotnet wrapper with full C++ and Python feature parity. The package is now publicly available on NuGet.

Features

  • Expanded the HDR feature to support input images with varying gains (previously only varying exposure times were supported).
  • Added support for extracting HDR images for Quad-HDR (for IMX900) and Clear-HDR (for Starvis 2 sensors), including cutting of lines and colums that don't contain valid image data, unpacking, and de-interleaving.
    • C++: Image.Deinterleave()
    • Python: Image.deinterleave()
    • .NET: Image.Deinterleave()
  • Added Chromatic Adaption to the default pipeline.

Improvements

  • Renamed the HDR calibrate function:
    • C++: Calibrate to EstimateResponseCurve
    • Python: calibrate to estimate_response_curve
  • Setting a hotpixel list with negative values now correctly throws an out of range exception.

Bug Fixes

  • Fixed an issue where the pipeline wrote to the same memory repeatedly when calling process sequentially. This might occur when an image pixel format is converted within the pipeline and no copy is done afterward.
  • Fixed an issue where the default pipeline did not reset its internal properties, leaving stale values in GammaFeature and DigitalBlackFeature.
    • The default pipeline will now reset the processing policy to Fast when calling reset to default.
    • In Python, the default pipeline will now reset its features correctly.
  • Fixed ToneCurveCorrectionModule applying stale values in the native backend when disabled.
  • Fixed DefaultPipeline.process in Python failing to guarantee a memory copy despite documentation claims.

Documentation

  • Made company logo clickable to return to the documentation homepage.
  • Added explicit warnings across all languages that the DefaultPipeline's process function can modify the input image, and warned against holding onto internal buffers returned from the pipeline.
  • Synchronized C++ and Python documentation and reordered programming languages alphabetically in the menus.

Documentation

  • Added serialization code snippets to the documentation.
  • Added missing “since” version annotations to API documentation.

Version 1.1.0

Features

  • Added a Python interface (see here for more information).
  • Implemented image pipeline in Python (see here for more information).
  • Added automatic type-checking mechanisms, external type-checker support, and mypy integration.
  • Added support for undistortion considering regions. (see more information for Python or for C++).
  • Add convertPixelFormatWithFactor to apply multiplication factor to image pixelwise while converting pixel format (see more information for Python or for C++).
  • Add ROI (Region Of Interest) to image metadata and use it in undistortion to make it possible to also undistort images with different ROI than used during calibration.
  • Move experimental features to stable:
    • Camera calibration: From now on, cameras might be calibrated using a supported calibration plate, which then results in intrinsic and extrinsic parameters. See Camera Calibration for more information
    • Undistortion: Added support for image undistortion using camera calibration results. This corrects lens distortion effects for more accurate image representation. See Undistortion for more information.
    • Workspace calibration: The workspace calibration calculates the extrinsic parameters based on a single image.
    • PointCloud: A point cloud is a set of data points defined in a three-dimensional (3D) coordinate system.
    • Median Filter: The MedianFilter class applies a median filter to reduce noise in an image. It replaces each pixel value with the median value of its neighboring pixels, based on a defined kernel size.
    • Painter: Can be used to paint simple things (e.g. a region) on images.
    • RegionSelector: Can be used to filter regions by different criteria.
    • Threshold: Can be used to apply a threshold to an image. See Thresholding and Segmentation for more information.
  • Add support for pixel format conversion from all bayer formats to format RGB10p32 (see here for more information).

Improvements

  • When saving a point cloud existing files are now overridden and no exception occurs.
  • Revisit binning/decimation implementation Replaced the binning/decimation function that internally allocates memory by a function with a previously allocated output image. The new implementation will also use multi threading and is faster now
  • Remove nodiscard macro and use the one from ids_peak_common.

Bug Fixes

  • Fix memory leak when creating regions or calibration results.
  • Change output of peak::icv::Serializer::Write to be empty, when the archive itself is empty Previously the functions output was just an empty json object.
  • Change peak::pipeline::detail::DownsamplingModule::ResetToDefault to not disable the module upon invocation.
  • Added validation to ensure that the origin of a calibration plate cannot be placed outside the plate’s defined coordinate system.
  • Fix a -Wundef warning when checking _MSVC_LANG before checking if it's defined.

Version 1.0.0

The IDS Industrial Computer Vision Library (ICV) is a modern C++ library for high-performance image processing in industrial vision applications. It builds on the foundation of the IDS Image Processing Library (IPL) and is designed to expand its capabilities with a modern architecture, improved performance, and greater flexibility.

The ICV library provides a configurable, modular image processing pipeline that converts raw sensor data into high-quality, ready-to-use images. The pipeline includes stages such as raw data unpacking, sensor artifact correction, debayering and format conversion. When combined with the IDS Auto Feature Library, the pipeline also supports advanced auto features like brightness, white balance, and focus.

The IPL will continue to be supported for existing projects, while the ICV evolves to cover and extend its feature set — making the ICV the recommended choice for new developments.
