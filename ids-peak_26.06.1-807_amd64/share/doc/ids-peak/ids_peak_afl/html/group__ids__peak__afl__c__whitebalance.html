Detailed Description

Automatic white balance control for color correction and temperature adjustment.

Auto white balance

Depending on the light source, light can have different color temperatures so that the images may have a color cast. At low color temperatures (e.g. light from incandescent lamps), the white content shifts towards a red hue. At high color temperatures (e.g. light from fluorescent lamps), the white content shifts a blue hue.

The white balance control feature uses the RGB gain settings of the camera to correct the white level. This is achieved by adjusting the gain controls until the red or blue channel matches the average brightness of the green channel.

Note
The Auto White Balance (AWB) regulation is subject to the following constraints:
  • It will not function if all color channels (B, G, R) have an intensity below 5.
  • It will not function if any individual color channel is 0.
  • It will not fuction if the inverse Color Correction matrix cannot be computed
If either of these conditions is met, the AWB algorithm cannot provide a reliable result and will return an error via the processing callback.

Enabling and automatically disabling the control function

For ongoing adaptations the Continuous mode has to be used so that it responds to deviations from the target value. To disable the control functionality automatically once the target value has been reached, (approximately) use the Once mode.

Configuring the control functions

Skip frames

The Skip frames setting defines how many frames should be skipped between processing operations. This parameter strongly influences both control speed and system stability.

How Skip Frames Works

When skip frames is set to N, the controller will:

  • Process frame 1
  • Skip frames 2, 3, ..., N+1
  • Process frame N+2
  • Skip frames N+3, N+4, ..., 2N+2
  • And so on...

Example: Skip frames = 3 means process every 4th frame (process 1, skip 3, process 1, skip 3...)

Dynamic Adjustment

Skip frames can be adjusted dynamically based on conditions:

Note
For higher frame rates, a larger value should be used for the Skip frames parameter. This reduces the number of automatic adjustments and improves system stability.
Different controllers can have different skip frame settings optimized for their specific requirements.

Region of interest (ROI)

If a smaller part of the image should be processed, a region of interest (ROI) can be set. The ROI allows focusing the auto feature analysis on specific areas while ignoring irrelevant parts of the image.

Note
If a ROI does not fit into the processed image dimensions, the processing callback is called with corresponding error status.


Note
The ROI for automatic control is set to the full size of the processed image by default.


Note
To reset a ROI to full image, all values must be set to 0, which will automatically use the complete image area.

Color Correction Matrix (CCM)

The Auto White Balance (AWB) module allows a Color Correction Matrix (CCM) to be configured.

Internally, the inverse of the configured Color Correction Matrix is calculated and used by the control algorithm so that the AWB regulation operates on the original, uncorrected image data. For this reason, the Color Correction Matrix must be set if the image has previously been processed using a Color Correction Matrix.

If no Color Correction Matrix is configured, an identity matrix is used by default.

The configured Color Correction Matrix must be invertible. If the inverse matrix cannot be computed, an error occurs within the processing callback when an image is processed.

Callback

It is possible to be informed for specific events via callbacks. Callbacks provide real-time feedback about controller operations and enable responsive application behavior.

Available Callback Types

Finished Callback

Finished will be called when the controller has completed its operation and reached the target value.

When called:

  • Controller completes adjustment in Once mode
  • Target value is reached within tolerance
  • Operation is cancelled or encounters an error

Processing Callback

Processing will be called during image processing to provide real-time feedback.

When called:

  • Each time an image is processed
  • Provides intermediate calculation results
  • Available in all controller modes

Callback Threading Considerations

Important Threading Notes:

  • Callbacks may be invoked from worker threads
  • Avoid blocking operations in callbacks
  • Keep callback execution time minimal
Note
The Finished callback will only be called when the controller runs in Once mode.

Examples

Note
For the automatic host control to work, the frames must be transferred to the manager. To reduce and simplify the sample code, the examples do not check the return values.
peak_afl_AutoFeatureManager_Create(&hManager, nodemapHandle);
// create a whitebalance controller within our manager
peak_afl_controller_handle hController = 0;
peak_afl_AutoFeatureManager_CreateController(hManager, &hController, PEAK_AFL_CONTROLLER_TYPE_WHITE_BALANCE);
// run in continuous mode
peak_afl_AutoController_Mode_Set(hController, PEAK_AFL_CONTROLLER_AUTOMODE_CONTINUOUS);
// submit the images
while(acquisitionRunning)
{
peak_afl_AutoFeatureManager_Process(hManager, imageHandle);
}

enum peak_afl_controller_whitebalance_component

White balance control components.

Defines the different camera parameters that can be adjusted by the white balance controller to achieve accurate color reproduction. Each component affects color balance differently and may have different performance characteristics.

Note
Component availability depends on camera capabilities
See also
peak_afl_AutoController_WhiteBalanceComponent_IsSupported()
Enumerator
PEAK_AFL_CONTROLLER_WHITEBALANCE_COMPONENT_INVALID 

Invalid or uninitialized component.

This value indicates an invalid component type and should not be used for component operations.

PEAK_AFL_CONTROLLER_WHITEBALANCE_COMPONENT_ANALOG_GAIN 

Analog gain white balance control.

Adjusts individual color channel analog gains before digitization. Provides the best signal-to-noise ratio for white balance correction but may have limited adjustment range.

Note
Best noise performance, preferred when available
PEAK_AFL_CONTROLLER_WHITEBALANCE_COMPONENT_DIGITAL_GAIN 

Digital gain white balance control.

Adjusts individual color channel gains in the digital domain after sensor readout. Wider adjustment range than analog gain but may amplify noise, especially in darker regions.

Note
Wider range but may amplify noise
PEAK_AFL_CONTROLLER_WHITEBALANCE_COMPONENT_COMBINED_GAIN 

Combined analog and digital gain control (combined)

Automatically manages both analog and digital gains for each color channel to achieve optimal white balance with best signal-to-noise ratio. Uses analog gain first, then digital gain for extended range.

Note
Recommended for best overall performance
PEAK_AFL_CONTROLLER_WHITEBALANCE_COMPONENT_HOST_GAIN 

Host-based software white balance.

Applies white balance correction in software on the host computer after image acquisition. Provides unlimited adjustment range but processes images after capture.

Note
Applied in software, may affect performance

Get the last auto average for a controller.

Used by Controllers processing a color image. This function retrieves the most recent calculated average values for each color channel (RGB) from the auto feature processing. These averages represent the calculated brightness levels for each color channel from the last processed frame.
