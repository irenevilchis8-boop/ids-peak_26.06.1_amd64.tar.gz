◆ Lock()

std::unique_ptr< NodeMap::ScopedNodeMapLock > peak::core::NodeMap::Lock ( )
inline

Acquires the NodeMap lock. Use this function to synchronize sequences of dependent NodeMap operations across multiple threads.

Note
Individual NodeMap operations are already thread-safe and do not require explicit locking. However, if multiple operations must be performed as a single logical unit, they should be protected by this lock to prevent interleaving with operations from other threads.

A common example is the use of selectors: changing a selector (e.g. setting "GainSelector" to "DigitalRed") and then accessing the selected node (e.g. "Gain"). Without holding the lock, another thread could change the selector between these operations, causing the wrong setting to be accessed.

Returns
A ScopedNodeMapLock that holds the lock until it is destroyed.
Since
1.2
Exceptions
InternalErrorExceptionAn internal error has occurred.

void peak::core::NodeMap::PollNodes ( int64_t elapsedTime_ms)
inline

Polls all nodes having a polling time.

Parameters
[in]elapsedTime_msThe elapsed time since the last poll in milliseconds.

See Node Caching and Polling Concepts for conceptual guidance on polling and cache interaction.

This method implements node polling on node map level. Pass the real elapsed time since the previous call; it is used to determine when nodes with a polling time need to be updated.

The API does not poll automatically. Applications should call this method periodically, for example from a service or UI loop while dynamic node state is in use.

◆ TryLock()

std::unique_ptr< NodeMap::ScopedNodeMapLock > peak::core::NodeMap::TryLock ( )
inline

Attempts to acquire the NodeMap lock without blocking. Use this function to synchronize sequences of dependent NodeMap operations across multiple threads. If the NodeMap is currently locked by another thread, this function returns immediately without acquiring the lock.

Note
Individual NodeMap operations are already thread-safe and do not require explicit locking. However, if multiple operations must be performed as a single logical unit, they should be protected by this lock to prevent interleaving with operations from other threads.

A common example is the use of selectors: changing a selector (e.g. setting "GainSelector" to "DigitalRed") and then accessing the selected node (e.g. "Gain"). Without holding the lock, another thread could change the selector between these operations, causing the wrong setting to be accessed.

Returns
A ScopedNodeMapLock if the lock was successfully acquired; otherwise, a null unique pointer.
Since
1.11
Exceptions
InternalErrorExceptionAn internal error has occurred.
